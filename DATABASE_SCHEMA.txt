## 🗂️ Database Schema

### 1. USERS Table
```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    salt TEXT NOT NULL,
    role TEXT NOT NULL CHECK(role IN ('owner','admin','manager','waiter','customer')),
    full_name TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    phone TEXT,
    is_active INTEGER NOT NULL DEFAULT 1,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**Purpose:** Stores user authentication credentials and profile information  
**Indexes:** Unique constraints on username and email  
**Roles:**
- `owner`: Full system access, can modify all data
- `admin`: Administrative access
- `manager`: Staff management and reporting
- `waiter`: Floor operations and table management
- `customer`: Order placement and order history

### 4. ORDERS Table
```sql
CREATE TABLE orders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    code TEXT NOT NULL UNIQUE,
    order_type TEXT NOT NULL CHECK(order_type IN ('dine_in','takeaway')),
    table_id INTEGER,
    customer_id INTEGER,
    customer_name TEXT,
    guests INTEGER NOT NULL DEFAULT 1,
    status TEXT NOT NULL CHECK(status IN ('pending','confirmed','preparing','ready','served','completed','cancelled')),
    subtotal REAL NOT NULL DEFAULT 0,
    tax REAL NOT NULL DEFAULT 0,
    service_charge REAL NOT NULL DEFAULT 0,
    discount REAL NOT NULL DEFAULT 0,
    total_amount REAL NOT NULL DEFAULT 0,
    payment_method TEXT,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(table_id) REFERENCES tables(id),
    FOREIGN KEY(customer_id) REFERENCES users(id)
);
```

**Purpose:** Stores order information with billing details  
**Fields:**
- `code`: Unique order identifier (e.g., "ORD-123456")
- `tax`: Calculated at 5% of subtotal
- `service_charge`: Calculated at 10% of subtotal
- `total_amount`: subtotal + tax + service_charge - discount

**Order Status Flow:**
1. pending → confirmed → preparing → ready → served → completed
2. Any status → cancelled

```sql
CREATE TABLE order_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id INTEGER NOT NULL,
    menu_item_id INTEGER NOT NULL,
    quantity INTEGER NOT NULL CHECK(quantity > 0),
    unit_price REAL NOT NULL,
    subtotal REAL NOT NULL,
    status TEXT NOT NULL DEFAULT 'queued',
    note TEXT,
    FOREIGN KEY(order_id) REFERENCES orders(id) ON DELETE CASCADE,
    FOREIGN KEY(menu_item_id) REFERENCES menu_items(id)
);
```

**Purpose:** Line-by-line breakdown of items in each order  
**Item Status:** queued → in_progress → ready → served

## 🔐 Security Implementation

### Password Hashing
- **Algorithm:** SHA256
- **Salt:** 32-character random string
- **Hash Formula:** SHA256(salt + password + salt)
- **Storage:** Only hash and salt stored, never plain password

### Authentication Flow
1. User submits username + password
2. System retrieves user record
3. Generates verification hash: SHA256(stored_salt + submitted_password + stored_salt)
4. Compares verification hash with stored password_hash
5. If match: Generate random 48-character token
6. Store token → user mapping in tokenStore (in-memory)
7. Return token to client for subsequent requests

### Token Management
- **Token Length:** 48 characters
- **Storage:** In-memory map (lost on server restart)
- **Usage:** All protected API endpoints require token header
- **Expiration:** Manual logout required (tokens persist until server restart)

## 💾 API Endpoints Using Database

### Authentication
- `POST /api/auth/login` → Query users table, generate token
- `POST /api/auth/register` → Insert new user to users table
- `POST /api/auth/logout` → Remove token from tokenStore

### Menu Operations
- `GET /api/menu/categories` → SELECT from menu_categories
- `GET /api/menu/items/all` → SELECT from menu_items with JOIN to categories

### Order Operations
- `POST /api/orders` → INSERT to orders + order_items tables
- `GET /api/orders` → SELECT from orders table

### Dashboard
- `GET /api/dashboard/stats` → Query orders table for metrics
- `GET /api/sales/summary` → Aggregate payment data

### Staff
- `GET /api/staff` → SELECT users WHERE role IN ('manager','waiter','admin','owner')

## 🛠️ Troubleshooting

### Issue: "Database locked"
- **Cause:** Multiple processes accessing SQLite
- **Solution:** Ensure only one server instance running

### Issue: "Duplicate entry" on seeding
- **Cause:** Running initialization twice
- **Solution:** Delete restaurant.db and restart

### Issue: Orders show ₹0 total
- **Cause:** Tax/service_charge calculation not applied
- **Solution:** Verify frontend calculateBill() function runs

### Issue: User login fails
- **Cause:** Password hash mismatch
- **Solution:** Check salt and hash algorithm match
